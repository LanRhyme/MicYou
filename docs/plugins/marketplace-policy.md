# 插件市场开发者规范与准入政策

本文档规定了发布到 MicYou 官方插件市场的插件准入要求、许可政策与安全审核流程

## 1 许可政策与例外条款

MicYou 遵循带有插件例外的 GNU GPLv3 许可证（MicYou Plugin Exception v1.0）

### 1.1 豁免范围
- 插件开发者可通过 MicYou 官方 Plugin API 与 Host API 编写独立插件，不受 GPLv3 传染限制
- 非商业用途的独立插件可自由采用任意开源协议（如 MIT、Apache-2.0）或闭源私有许可

### 1.2 商业化插件政策
- 任何通过 MicYou 插件进行付费销售、商业授权或订阅营利的行为，均需事先取得 MicYou 版权方的书面授权或商业许可
- 企业内部私有开发且不进行公开商业分发的工具插件不受商业许可限制

## 2 官方插件市场准入要求

发布至官方插件市场（MicYou Plugin Marketplace）的插件需满足以下条件之一：

1. **开源准入**：插件源码完全公开，且采用与 GPLv3 兼容的自由/开源许可证（如 GPL-3.0、MIT、Apache-2.0 等）
2. **审查准入**：闭源或商业化插件需经过官方安全与合规审查，并获得上架许可认证

## 2.5 本地化展示

市场页按用户界面语言展示插件名称与描述：条目 manifest 提供 `nameI18n` /
`descriptionI18n`（BCP-47 标签 → 文本）时优先展示，缺失时回退基础 `name` /
`description`（**旧条目不受影响**）。新提交的市场条目**建议**至少提供 `zh-CN`
与 `en` 两种标签；详见开发指南「本地化适配」一节。

## 3 安全与合规规范

- **权限最小化**：插件 manifest 必须如实声明所需能力（capabilities），严禁申请未实际使用的敏感权限
- **网络与隐私**：涉及网络请求或用户数据采集的插件必须在文档中明确告知用途，严禁暗中上传用户音频或敏感信息
- **沙箱与存储**：文件读写必须限定在宿主分配的插件独立目录内
- **禁止恶意行为**：严禁包含任何挖矿、恶意后门、劫持系统设备或绕过宿主安全机制的代码

## 4 提交流程与分发架构

1. 开发者在自身代码仓库完成开发并通过 CI 打包构建产物发布至 Release
2. 在官方市场索引仓库提交 Pull Request，登记 `plugin.json` 元数据与发布下载链接
3. 自动化 CI 校验清单格式、签名与能力声明
4. 人工审核团队进行代码安全与许可审查，合规后合并并同步至市场索引
